Team Notes Service

A REST backend where small teams share notes. Every member of a team can read and edit its notes. Outsiders can't tell that a note exists, and two people editing at once can't silently overwrite each other.

The model

There are three things: users, teams and notes. A user belongs to teams as an owner or a member. A note belongs to exactly one team, keeps its author, and carries a version that goes up by one on every change.

Visibility: one 404 for everything you can't see

A note in someone else's team, a note that never existed, a malformed id, a deleted note and an unknown route all return the same bytes, a 404 problem document. A curious user learns nothing by probing ids. The one 403 in the API goes to a team member who isn't the owner and tries to change membership, because they can already see the team.

Concurrency: no lost updates

Every read returns ETag: "<version>". To edit, you send it back in If-Match. The server checks and increments in one statement, UPDATE … WHERE id = ? AND version = ?. If someone else got there first, you get 412 and the current ETag, so you can re-read and retry. With no precondition at all you get 428: unconditional overwrites aren't allowed.

Delete and restore

DELETE is a soft delete. It's idempotent, keeps the content, and leaves the version alone. POST /notes/{id}/restore brings the note back and bumps the version, so anyone still holding a version from before the delete gets 412 instead of quietly editing a resurrected note. ?archived=true lists the team's trash.

Errors and their order

Every error is an RFC 9457 application/problem+json document. When a request breaks several rules at once, the first one in this chain wins, in every implementation:

401→404→415→413→400→422→428→412

Authentication → visibility → media type → size → JSON syntax → validation → precondition → version. Visibility is decided before anything about the body is revealed.

Teams

Anyone can create a team with a readable slug and becomes its owner. Only the owner adds or removes members. Access follows membership immediately: a removed member gets the same 404 on their very next request, even for notes they wrote. Those notes stay with the team. The last owner can't leave, so no team is ever left without an administrator.
